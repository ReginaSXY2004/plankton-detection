# 真实水体环境部署风险分析

## 当前系统

```text
YOLO 检测
→ detection 后处理
→ tracker 关联
→ confirmed 计数
→ best crop 保存
→ CSV / 视频输出
```

当前系统已经具备原型验证能力，但真实水体环境与实验室视频差异很大。

下面只保留最核心、影响最大的风险。

---

# 1. 真实水体杂质导致误检暴涨

真实环境中可能出现：

- 气泡
- 泥沙
- 悬浮颗粒
- 反光
- 镜头污点
- 植物碎屑

当前 blob filter 只能过滤部分圆形亮斑。

风险：

```text
杂质被识别成微生物
```

后果：

- 计数虚高
- tracker 出现大量假轨迹
- best crop 保存大量垃圾图

---

# 2. 漏检可能比误检更严重

真实环境中：

- 微生物更小
- 更模糊
- 更透明
- 对焦不稳定
- 光照变化更大

风险：

```text
目标根本没有进入 tracker
```

后果：

- 计数长期偏低
- 某些类别长期被低估

真实部署前必须做：

```text
人工标注 benchmark 视频
```

不能只看最终计数。

---

# 3. 水流会破坏 tracker 的运动假设

当前 tracker 默认：

```text
目标运动连续、相邻帧位移有限
```

但真实水体中：

- 水流
- 相机抖动
- 机器人运动

都可能让目标突然位移。

风险：

```text
旧 ID 丢失
→ 新 ID 出生
→ 重复计数
```

这是未来最可能出现的问题之一。

---

# 4. 多目标遮挡仍可能导致 ID swap

当前 tracker 已经加入：

- IoU
- 方向惩罚
- reconnect
- no-spawn zone

但仍没有真正的 ReID 外观特征。

当多个目标：

- 靠近
- 重叠
- 交叉
- 大小相似

时仍可能出现：

```text
A 的 ID 接到 B 身上
```

如果未来要做：

```text
个体行为分析
```

这是核心问题。

---

# 5. No-spawn zone 可能造成漏计

当前 no-spawn zone 可以减少重复 ID。

但在密集场景：

```text
新目标可能因为离旧轨迹太近而无法出生
```

结果：

- 重复计数减少
- 漏计增加

这是典型 precision / recall trade-off。

---

# 6. 当前计数逻辑不一定符合真实业务目标

当前逻辑：

```text
confirmed 一次 → count +1
```

它更像：

```text
累计出现过的独立目标数
```

但真实业务可能需要：

- 当前瞬时数量
- 单位时间通过量
- 单位体积浓度
- 某区域实时密度

如果业务定义不清：

```text
算法正确 ≠ 业务正确
```

---

# 7. 不同倍率会导致整体参数失效

倍率变化不只是“目标大小变化”。

还会影响：

- 运动像素速度
- 视野范围
- 景深
- 模糊程度
- bbox 分布

因此：

```text
同一个 tracker 参数
在不同倍率下可能完全失效
```

必须分别 benchmark：

```text
0.2x / 0.5x / 1x / 2x
```

---

# 8. 对焦与模糊会同时影响 detection 和 best crop

真实环境中：

- 自动对焦
- 水流
- 机器人震动

都会造成模糊。

后果：

- detection confidence 下降
- tracker 更容易断轨
- best crop 大量 low_sharpness

如果：

```text
low_sharpness 占比很高
```

说明首先要解决的是成像系统，而不是 tracker。

---

# 9. 没有真实环境数据闭环，系统会停留在实验室效果

真实环境问题无法靠一次调参解决。

需要形成：

```text
真实视频
→ 自动推理
→ 保存错误案例
→ 人工复查
→ 重新训练
→ 再 benchmark
```

否则容易出现：

```text
某几个视频效果很好
换一段水体立刻失效
```
