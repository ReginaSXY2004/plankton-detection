# 真实水体环境部署风险分析（微生物检测追踪系统）

## 项目背景
当前系统流程：

```text
视频输入 → YOLO检测 → 去重/亮斑过滤 → Tracker追踪 → 稳定后计数 → 保存最佳图 → 输出视频/CSV
```

该系统已具备原型验证能力，但部署到真实水体环境时，可能出现检测稳定性、追踪连续性、计数准确性等问题。

---

# 一、可能遇到的核心问题

## 1. FPS 不一致导致参数失真
当前许多逻辑按“帧数”控制：

```python
CONFIRM_MIN_HITS = 6
FINALIZE_MISSED_THRESH = 8
max_missing = 18
```

若视频帧率变化：

- 30 FPS：6帧 = 0.2秒
- 10 FPS：6帧 = 0.6秒

会导致：

- 目标确认变慢
- finalize 延迟
- 短暂目标漏计

### 建议
改为按秒控制，再根据 FPS 自动换算。

---

## 2. 水流导致位移过大，Track 容易断裂
真实水体中目标移动来源：

- 自主游动
- 水流推动
- 镜头扰动

若相邻帧位移过大，旧轨迹无法匹配到新检测框，会产生：

- ID丢失
- 新ID重建
- 重复计数

### 建议
动态调整距离阈值，并结合 FPS 自适应。

---

## 3. 多目标交叉时 ID 交换
多个微生物靠近、交叉、重叠时，可能出现：

- A轨迹接到B身上
- B轨迹接到A身上
- 分类结果污染

当前 tracker 无外观特征（ReID），复杂遮挡场景风险较高。

### 建议
加入 crop 特征相似度 / embedding 匹配机制。

---

## 4. 气泡、杂质、反光误检
真实水体常见干扰：

- 气泡
- 悬浮颗粒
- 镜面反光
- 镜头污点

即使圆斑过滤存在，也可能仍被识别成微生物。

### 建议
增加真实环境负样本数据集重新训练。

---

## 5. 新物种泛化能力不足
训练数据若集中于固定倍率、固定物种、固定光照，则真实环境可能出现：

- 新物种
n- 新姿态
- 新背景
- 新倍率

导致：

- 低置信度
- 漏检
- 全部归类到 unknown

### 建议
持续扩充真实数据集，做增量训练。

---

## 6. Best Crop 评分偏差
当前评分：

```python
sharpness + conf + area
```

可能偏爱：

- 大目标
- 高亮目标
- 高边缘目标

不一定是人工最满意截图。

### 建议
增加类别权重、人类可读性评分。

---

## 7. 实时写视频拖慢速度
若同时执行：

- 视频保存
- CSV写入
- crop保存
- 推理

可能导致处理 FPS < 相机 FPS。

结果：

- 实时延迟
- 缓冲堆积
- 掉帧

### 建议
部署时异步写盘，多线程输出。

---

## 8. 当前计数逻辑 ≠ 真实个体数
当前逻辑：

```text
track hits >= threshold → count +1
```

风险：

- 同一目标断轨后重复计数
- 短暂目标未达 hits 被漏计

### 建议
明确业务定义：

- 当前视野累计个体数？
- 当前瞬时在场数量？
- 单位时间通过量？

---

## 9. 分类投票被早期错误污染
当前采用多数投票：

```python
class_votes
```

若前几帧模糊识别错误，可能影响最终类别。

### 建议
采用后期高置信帧加权投票。

---

## 10. 倍率变化导致参数整体失效
变化因素：

- 分辨率变化
- 镜头倍率变化
- FOV变化
- 像素尺寸变化

影响：

- 距离阈值
- best crop 最小尺寸
- imgsz
- no_spawn_radius

### 建议
建立不同倍率配置表（你已在做，这是正确方向）。

---

# 二、最优先升级建议（按收益排序）

## 第一阶段（立刻做）

1. 时间参数改按秒控制
2. 输出错误分析 CSV
3. 收集真实水体测试视频 benchmark

## 第二阶段（增强稳定性）

4. tracker 加外观特征辅助匹配
5. 多倍率自动切换参数
6. 异步写视频提升 FPS

## 第三阶段（产品级）

7. UI 实时统计面板
8. 数据库存档
9. 长期趋势分析
